# Transfer / Quick Share competitor findings (2026-11-21)

Clones: scratchpad/clones/{NearDrop,rquickshare,localsend}. gh search rate-limited, so other Mac Quick Share projects were NOT surveyed (only these three read).
Licenses (from LICENSE files): NearDrop = Unlicense (public domain, copy OK); rquickshare = GPL-3 (ideas only); localsend = Apache-2.0 (adaptable with credit).

## What each does
- NearDrop (Swift, menu bar, sandboxed): Wi-Fi LAN only, receive + send. Receive: NWListener + NetService `_FC9F5ED42C8A._tcp.` always visible-to-everyone while running; saves to Downloads (sandbox entitlement downloads.read-write), de-dupes names "x (1)". Notification with Accept/Decline actions (UNNotificationCategory, authenticationRequired on Accept) showing PIN. URLs sent from phone open in browser; plain text saved to dated .txt. Send: Share extension (Finder Share menu / Safari) -> NWBrowser discovery; chunk 512 KiB read; progress. Because macOS cannot set BLE service data, it uses the **QR code trick**: Mac shows QR (https://quickshare.google/qrcode#key=...), phone scans, phone starts advertising mDNS incl. QR TLV (type 1; advertising token, or AES-GCM encrypted name for hidden devices) -> Mac sees phone. PROTOCOL.md documents all of it. Distribution: GitHub zip, Homebrew tap (`brew install grishka/grishka/neardrop`, xattr -d quarantine), not notarized. No history, no auto-accept, no resume.
- rquickshare (Rust+Tauri, Linux-first, macOS "should work"): Wi-Fi LAN only. BLE: **blea.rs** advertises Broadcast with service UUID 0xFE2C and fixed 26-byte service data (`fc 12 8e 01 42 00..` + random tail) via BlueZ `bluer` -> this is what wakes Android mDNS. Linux-only because CoreBluetooth cannot set service data. **ble.rs** is a btleplug *scanner* on 0xFE2C that fires "a device nearby is sharing" (rate limit 30 s) -> app then becomes visible. Send chunk 512 KiB, SANE_FRAME_LENGTH 5 MiB. Phone appears/disappears because Android de-registers mDNS until the next BLE broadcast. Documents Android workaround: launch activity `com.google.android.gms.nearby.sharing.ReceiveSurfaceActivity` or action `com.google.android.gms.RECEIVE_NEARBY` (Samsung differs).
- LocalSend (Flutter + Rust core, Apache-2.0): its own protocol (not Quick Share), HTTPS with self-signed per-device cert, fingerprint = cert hash (mTLS cert fingerprint cannot be spoofed), UDP multicast 224.0.0.167:53317 announce + subnet HTTP scan fallback ("Announced but could not be reached" handling), optional PIN, **Favorites** + `quickSave` / `quickSaveFromFavorites` auto-accept, "Accept and pair" (future requests auto-accepted), single active session, receive history provider, autoFinish, macOS Share extension (ShareExtension -> security-scoped bookmarks via shared UserDefaults), drag-drop ContentDropView, Homebrew cask + CLI, App Store (sandbox, user-selected read-write), WebRTC/web-share link for browsers. Streaming request body per file; no resume.

## Quick Share support matrix on Mac
| Feature | NearDrop | rquickshare | DroidDock |
|---|---|---|---|
| Receive | yes | yes | yes (quickshare/server.rs, opt-in, 16 conn / 3 per IP caps) |
| Send | yes (needs QR or phone screen open) | yes (BLE wake on Linux only) | yes (client.rs, sender.rs; phone must be on Quick Share screen) |
| BLE wake from Mac | impossible (QR instead) | Linux only | none; sender.rs states limit |
| Bandwidth upgrade (WiFi Direct/hotspot/BT) | no | parses Medium enum, LAN only | no |
| Chunk | 512 KiB | 512 KiB | 64 KiB (client.rs:43) |
| Auto-accept / history / pairing | no | no | no auto-accept; transfer_log exists |

## Ideas for DroidDock (value / effort / license / session)
1. QR-code "wake phone" for Mac->phone Quick Share send. Show QR (quickshare.google/qrcode#key=...) in QuickShareSendSheet; derive advertising token + name key with HKDF per NearDrop PROTOCOL.md; phone scans, starts advertising with QR TLV, our sender.rs browses mDNS and matches token. Fixes the biggest send gap (README says phone must be open+visible). H / M / Unlicense spec (clean-room re-implement anyway) / new (quickshare-send). Files: core/src/quickshare/sender.rs, client.rs, mac/.../QuickShare/QuickShareSendSheet.swift.
2. Hidden-device-aware discovery: parse TLV type 1 and visibility bit in sender.rs (probably partially). M / S / Unlicense / new.
3. Raise Quick Share send CHUNK from 64 KiB to 512 KiB (both NearDrop and rquickshare use 512 KiB; mind progress throttling at sender.rs:201 and 5 MiB frame sanity cap). Should speed LAN sends; verify with local loopback test. M / S / free / new.
4. Android "open Quick Share receive screen" helper: since DroidDock already runs on the phone, add a "Show on phone" action over the WS link that launches com.google.android.gms.nearby.sharing.ReceiveSurfaceActivity / RECEIVE_NEARBY (Samsung differs) so the phone becomes visible with no QR/BLE. Uses only a documented Android intent (idea from rquickshare README, no code). H / S / ideas only / new (or bt-offline adjacent). Files: droiddock-android BridgeService + sender.rs trigger.
5. Auto-accept rules + "Accept and pair" (LocalSend favorites/quickSaveFromFavorites): for Quick Share receive, remember sender device (by endpoint name or UKEY2 public key) and auto-accept; optional size cap and folder-per-sender. Currently every request prompts (server.rs:232 Introduced -> quickshare-request). H / M / Apache-2.0 idea / new. Note: Quick Share has no authenticated identity for strangers, so key by name+device type and show PIN anyway; keep opt-in.
6. Notification actions for incoming Quick Share: UNNotification with Accept/Decline + PIN while app is in background (NearDrop AppDelegate.swift, categories INCOMING_TRANSFERS). Check DroidDock's existing banner path; add action buttons. M / S / Unlicense / new.
7. Text and URL payloads: NearDrop opens received URLs and saves text to a dated .txt; DroidDock could route Quick Share text to clipboard/history (clipboard feature exists) and URL to "Open / Copy" banner (not auto-open). M / S / Unlicense / new.
8. Finder Share extension (NSSharingService appex, needs bundle+entitlement; hand off via security-scoped bookmarks in app-group defaults like LocalSend app/macos/ShareExtension). DroidDock has NSServices only (mac/Info.plist:36, ServicesProvider.swift) which is hidden in submenu. Swift PM build with no Xcode makes an appex hard. M / L / Apache-2.0 pattern / new.
9. Menu-bar drop target: status-item drop (like LocalSend ContentDropView) so files can be dragged to the menu bar icon and sent to the last/paired phone. Drop targets exist on cards (PhoneCard.swift:20, ClassicShell.swift:171) but not the status item. M / S / Apache idea / new.
10. Discovery robustness (LocalSend): mDNS-only today (mdns.rs, SERVICE_TYPE `_droiddock._tcp.local.`) plus UDP DISCOVER2; LocalSend adds subnet HTTP probing and flags "announced but unreachable" peers. Surface "seen but unreachable" in the setup check (helps hangs session diagnosis). L-M value / S / Apache / hangs.
11. Passive "phone is sharing nearby" hint (rquickshare ble.rs): CoreBluetooth central CAN scan for UUID 0xFE2C service data; when Android broadcasts while the user opens its share sheet, auto-open DroidDock's send sheet / raise Quick Share send list. No advertising needed. Reuses CoreBluetooth central already built for the BLE link. M / M / GPL (idea only; scanning for a public UUID is not copyrightable, write own) / bt-offline.
12. Resume / checksum: nobody here does resume. DroidDock transfer.rs has a bounded outbox + 256 KiB chunk and WebDAV supports Range; adding resume for the paired-phone path (offset in fs-pull/push) would beat all three. M / M / n/a / hangs.
13. Bandwidth upgrade: no Mac project does it (WiFi Direct absent on macOS; AWDL incompatible). Don't chase. Hotspot-medium upgrade (phone SoftAP) is theoretically possible but large. L / L / n/a / skip.
14. Distribution: NearDrop uses Homebrew tap + xattr instructions; LocalSend has Homebrew cask and App Store. DroidDock (self-signed, not notarized) could publish a Homebrew cask/tap with postflight xattr removal. Sandbox note: both projects sandbox with downloads.read-write + network client/server; DroidDock is not sandboxed (needs adb, WebDAV, virtual display) so App Store is not realistic. M / S / free / new.
15. Folder handling: NearDrop receives flat files only; DroidDock server.rs:273 already returns folder for multi-file. Add "reveal in Finder", dedupe ("name (1)") check and folder/zip send for Quick Share (client.rs mime handling) - verify. L-M / S / Unlicense / new.
16. Received-file history UI: LocalSend has receive_history_provider; DroidDock has transfer_log.rs (Dir::ToMac/ToPhone) - confirm TransfersScreen shows Quick Share entries with open/reveal/copy-path. L / S / Apache idea / new.
