## What DroidDock does today (verified)
- ADB mode launches the stock scrcpy server jar with control=false, audio=false, h264 only, video_bit_rate, max_fps, max_size (droiddock-native/core/src/scrcpy_client.rs:179-200). Input is `adb shell input ...` per event (mirror.rs adb_input ~L288-345, uses adb::shell_input): one process spawn per tap/key, ASCII-only text.
- Wi-Fi mode: MirrorService.kt builds its own MediaCodec H.264/HEVC: VBR, KEY_PRIORITY 0, OPERATING_RATE, MAX_B_FRAMES 0, KEY_LATENCY 1, requestSyncFrame (MirrorService.kt:127-160, 483-525), MediaProjection VirtualDisplay with only FLAG_PUBLIC (L220).
- Camera: MirrorService source="camera" exists, no macOS virtual webcam.

## scrcpy facts worth knowing (read in code)
1. Encoder (video/SurfaceEncoder.java:308-340): KEY_REPEAT_PREVIOUS_FRAME_AFTER=100ms (static screens still emit a frame, recovers quality, shows first frame), KEY_PRIORITY 0, KEY_LATENCY 1, private "max-fps-to-encoder" key, COLOR_RANGE_LIMITED, KEY_FRAME_RATE fixed 60 (VFR). Encoder fallback loop: on failure retries with smaller size (L100-200). Reset-on-resize/rotation by signalling EOS and reconfiguring (CaptureControl RESET_REASON_*), no frame-rate/restart of whole session.
2. Resize debouncer 300 ms for flex display (display/DisplayResizeDebouncer.java).
3. --new-display (video/NewDisplayCapture.java:213-235): flags PUBLIC|PRESENTATION|OWN_CONTENT_ONLY|SUPPORTS_TOUCH|ROTATES_WITH_CONTENT, +TRUSTED|OWN_DISPLAY_GROUP|ALWAYS_UNLOCKED|TOUCH_FEEDBACK_DISABLED on A13, +OWN_FOCUS|DEVICE_DISPLAY_GROUP on A14, SHOULD_SHOW_SYSTEM_DECORATIONS and DESTROY_CONTENT_ON_REMOVAL optional, setDisplayImePolicy (IME shown on VD). Flex display = VirtualDisplay.resize() driven by the client window size.
4. Audio: AudioDirectCapture (REMOTE_SUBMIX / MIC via AudioRecord built with FakeContext as com.android.shell, Android 11 workaround launching HeapDumpActivity, Vivo workaround) and AudioPlaybackCapture (hidden AudioMixingRule/AudioPolicy via reflection, A13+; "keepPlayingOnDevice" and voiceCommunicationCaptureAllowed). 48 kHz stereo s16, Opus/AAC/raw.
5. Camera (video/CameraCapture.java): Camera2 via shell identity, size/fps/aspect selection, constrained high-speed sessions. Desktop side only exposes it via v4l2loopback (Linux). NO macOS virtual camera exists in scrcpy; none of scrcpy/QtScrcpy/escrcpy/handset provide a CoreMediaIO camera.
6. UHID (control/UhidManager.java) opens /dev/uhid from shell uid; keyboard/mouse/gamepad as real HID devices (so IME is not triggered, games see real gamepad). AOA variant over USB OTG (app/src/usb/).
7. Clipboard: Controller.java:144-160 listens to PrimaryClipChanged via hidden ClipboardManager -> pushes to desktop; desktop paste sends SET_CLIPBOARD with paste flag.
8. Screen off while mirroring: Device.setDisplayPower(false) via SurfaceControl/DisplayControl (not a lock), restore in CleanUp.java (also restores screen_off_timeout, stay_awake). Server-side cleanup runs even if client dies.
9. Tunnel (app/src/adb/adb_tunnel.c): try `adb reverse`, fall back to `adb forward` automatically (needed for adb connect).
10. Desktop UX: shortcut modifier (MOD+f fullscreen, +r rotate, +g resize-to-fit, +w fit-window pixel perfect, +b/backspace back, +h home, +s app switch, +n notif panel, +o screen off, +c/x/v clipboard, +i FPS counter, +z/arrows), drag-drop .apk -> adb install, drop other file -> adb push (input_manager.c:1127-1210, file_pusher.c), --record mp4/mkv, --tcpip, OTG mode (control phone with no screen).

## Other tools worth learning from
- handset (Apache-2.0, Rust, mac): reuses unmodified scrcpy server (ADR 0003), VideoToolbox decode (0018), raw-PCM audio with 40 ms prebuffer / 120 ms cap that drops oldest (0007), QR + `adb mdns services` pairing UI (0016), local control socket + MCP server for agents (0044/0048), WebRTC share of the same H.264 to a browser without re-encode, keyframe on demand via scrcpy reset-video msg type 17 with SPS/PPS prefixed on every keyframe (0039), uiautomator screen-as-text (0045).
- dex-for-mac (MIT): menu bar app that launches scrcpy --new-display with resolution/DPI presets for Samsung DeX desktop mode (app/DeXBar.swift).
- escrcpy (Apache): multi-device single window with broadcast input and batch APK install/screenshots, keyboard mapping (touch/joystick/swipe) on top of mirror, LAN auto-discovery, Gnirehtet reverse tethering, device presets.
- QtScrcpy (Apache): JSON keymaps for games (keymap/*.json), group control across devices, wifi connect UI.
- Cam2Camera (iPhone2MacVirtualWebcam): reference architecture for a macOS virtual camera: app receives stream, a CMIOExtension (system extension, VirtualCameraExtensionProvider.swift) exposes a sink stream the app pushes decoded frames into. Requires system-extension approval + Developer ID/entitlement; no license -> ideas only.
- droidcam-obs-plugin (GPL-2): OBS plugin route to expose phone camera; ideas only. OBS 30+ ships its own mac virtual camera, so "phone camera as OBS source" is a cheap interim.

## Ideas (value / effort / license / session)
1. Make ADB-mode input fast and reliable: enable control=true and speak scrcpy's control protocol (touch/key/scroll/text/clipboard/back-or-screen-on/rotate/set-power, control/ControlMessageReader.java) instead of `adb shell input` per event (mirror.rs adb_input; scrcpy_client.rs:187 control=false). Kills process-spawn lag, gives multi-touch, unicode text, scroll, long-press, and keyframe request (reset_video msg 17). Apache: protocol can be reimplemented/adapted with credit. H / M / Apache / hangs (also removes adb spawn storms) + new "mirror".
2. Encoder tuning for Wi-Fi mode (MirrorService.kt:127-160): add KEY_REPEAT_PREVIOUS_FRAME_AFTER=100000 us (static screen, late joiners, recover quality), "max-fps-to-encoder" private key, COLOR_RANGE_LIMITED, keep fixed KEY_FRAME_RATE with VFR; add encoder-failure fallback that retries at smaller size (SurfaceEncoder.java:100-200). H / S / Apache / hangs.
3. Rotation/resize without restarting the session: scrcpy resets codec in place with EOS + reconfigure and re-sends SPS/PPS before each keyframe; debounce resize 300 ms (DisplayResizeDebouncer). Check DroidDock re-prefixes config on every IDR for joiners (handset ADR 0039). M / S / Apache / hangs.
4. Second screen quality: copy the NewDisplayCapture flag ladder (TRUSTED, OWN_DISPLAY_GROUP, ALWAYS_UNLOCKED, TOUCH_FEEDBACK_DISABLED, OWN_FOCUS) and setDisplayImePolicy, plus flex-display resize from Mac window size. Only reachable via shell uid (ADB mode / Shizuku-like); Wi-Fi MediaProjection mode is limited to FLAG_PUBLIC (MirrorService.kt:220). Check existing second-screen code before changing. H / M / Apache / new (second-screen).
5. Server-side screen-off while mirroring: SurfaceControl/DisplayControl setDisplayPower(false) + restore-on-exit cleanup that survives a dead client (CleanUp.java, Device.java). Ties directly to the existing keeper/locked-dark VD problem. M / S (just pass `power_off_on_close`, `control` messages) / Apache / hangs.
6. macOS virtual camera for phone camera: no competitor does it in scrcpy-land. Build a CMIOExtension (system extension) with a sink stream like Cam2Camera's VirtualCameraExtensionProvider.swift; Rust core hands decoded frames to a small Swift helper. Needs signed host app + user approval; ad-hoc/self-signed (DroidDock is not notarized) is the big blocker, so ship a cheaper interim: "Copy as OBS source" (window capture / virtual window) and a notarization decision. H / L / ideas only (Cam2Camera has no license) / camera.
7. Camera quality knobs from CameraCapture.java: choose camera id/facing, aspect, explicit size, fps, high-speed session, plus camera on shell-uid via scrcpy `video_source=camera` in ADB mode (no CAMERA permission prompts, works while phone app backgrounded). M / M / Apache / camera.
8. Audio forward: for ADB mode pass audio=true with audio_codec=raw or opus; copy handset's playback ring (40 ms prebuffer, 120 ms cap, drop oldest) for latency control. A13+ AudioPlaybackCapture (hidden AudioPolicy via reflection, keepPlayingOnDevice) also means the phone keeps playing. Call audio (voiceCommunicationCaptureAllowed true in AudioPlaybackCapture.java:72-74) is the same primitive the bt-calls session found as CALL_AUDIO_INTERCEPTION. M(for general) /H(for calls) / M / Apache / bt-calls.
9. Pairing/discovery UX from handset ADR 0016 and escrcpy qr-action: single sheet with Wi-Fi / QR tabs, poll `adb mdns services` only while sheet is open, QR payload `WIFI:T:ADB;S:name;P:pass;;`, auto `adb pair` then connect. DroidDock already does QR pair + mDNS reconnect (adb.rs ~1062-1064, 998-1062); remaining gaps: show "phone is on pairing screen" detection and `adb reverse`->`forward` automatic fallback (adb_tunnel.c). M / S / Apache / bt-offline (alternate link) + hangs.
10. Mirror window UX: drop .apk -> adb install, drop other files -> push to Download (file_pusher.c), shortcut set (fullscreen, rotate, resize-to-fit, pixel-perfect, FPS counter, screen-off toggle, back/home/switch with Cmd combos), record mp4 (ffmpeg sidecar in handset ADR 0008 is GPL-risk; use VideoToolbox/AVAssetWriter on the H.264 packets directly instead). M / S / Apache / new (mirror polish).
11. Device presets + multi-device: save per-device profiles (bitrate, fps, max size, codec, camera/display settings) and a multi-device grid with broadcast input (escrcpy, QtScrcpy group control). L-M / M / Apache / new.
12. Agent/automation surface: local control socket + MCP server and uiautomator screen-as-text (handset ADR 0044/0045/0048); DroidDock already has AppleScript, an MCP/CLI would be cheap on top of ⌥Space command actions. L-M / M / Apache / new.
13. HID injection for games/keyboard: UHID keyboard/mouse/gamepad (control/UhidManager.java) avoids IME and works with game controls; escrcpy/QtScrcpy keymap JSON for touch-mapped keys. L / M / Apache / new.
14. Clipboard parity: scrcpy listens for PrimaryClipChanged from shell uid (Controller.java:144-160), bypassing the Android 10+ background clipboard block that DroidDock needs the a11y service for in ADB mode. L / S (comes with idea 1) / Apache / new.
15. Samsung DeX preset: dex-for-mac shows `--new-display` + Desktop Mode on One UI 8 / Android 16 gives a full desktop; DroidDock could add "Desktop mode" button if scrcpy server >=4.1 and Samsung. L-M / S / MIT / new.

## Caveats
- DroidDock input on Wi-Fi uses AccessibilityService; ADB-mode `adb shell input` is the weak link (spawn per event). Enabling the control socket is the single largest quality jump.
- Everything in scrcpy server that uses hidden APIs (AudioPolicy, SurfaceControl, ClipboardManager, uhid) only works as shell uid; it cannot move into the Android app without root/Shizuku/Wireless-debugging self-ADB.
- Not verified on device; read-only code comparison only.
